## 2. 规划调整

保留原阶段编号，将依赖前移：Phase 1 从第一次真实调用就记录最小执行事件；Phase 2 先完成二维知识编辑再连接 3D；Phase 3 完成执行图展示及性能测量。这样每个可视节点都有真实数据来源。

## 3. 分阶段任务与验收

### Phase 0：环境、设计与应用壳

依赖：明确仓库边界，检查开发工具链。按以下顺序执行：

1. 只读检查 Windows、Node、包管理器、Rust MSVC、Git、C++ Build Tools、WebView2、Ollama 和 NVIDIA 驱动；记录版本、缺项和对开发的影响。
2. 产出 ADR：单应用目录；SQLite 库；执行事件与知识版本语义。需要偏离总纲的重大架构决定先单独确认。
3. 根据规范画出对话、知识、图谱、设置四页及首次启动流程，确认主操作、空态和窄窗口布局。
4. 初始化最小 Tauri + React + TypeScript 工程，建立主题变量、应用框架、主导航和明确标注的占位页。
5. 按当期需要创建 README、PRD、architecture、database-schema、security、test-plan、milestone-log；内容有实际决定，避免空文件堆积。
6. 类型检查、前端构建、Rust 检查；环境允许时启动 Tauri，检查窗口缩放和键盘导航。

验收：应用可启动、四页可切换、当前入口明确、窄窗口主操作可达；所有未接入功能明确标注；没有假模型连接、假聊天成功或假数据持久化。环境缺项时记录阻塞，不能把仅浏览器运行视为桌面验收通过。

### Phase 1：真实对话与本地保存

状态：2026-10-16 核心验收通过，最终全套检查 10/10；人工补充项见里程碑。

依赖：Phase 0 通过；本地 Ollama 和实际可运行模型可用。

1. 建立工作区、会话、消息、运行和最小事件表及迁移。
2. 实现模型检测、已安装模型列表、连接测试；通过实际 `ollama show` 核对模型信息。
3. 实现 Rust 流式请求、取消、超时、一次一个生成任务以及前端消息状态。
4. 输入先持久化，输出保存检查点和最终状态；记录接收请求、上下文准备、模型请求、结束/失败/取消事件。
5. 做可读的二维执行详情，展示本次模型配置和实际上下文摘要，不等待 3D 完成才可排错。
6. 接入会话切换、重命名、重启恢复及中断恢复提示。

验收脚本：新建工作区 → 发送问题得到真实回答 → 停止第二次生成 → 切换会话 → 重启应用 → 原会话和部分回答存在 → 停止 Ollama 再请求 → 显示可恢复错误。工作区 B 不能读取 A 的消息。

关键检查：流分片边界与畸形数据、取消/完成竞争、迟到事件、迁移与重启、工作区隔离。记录真实硬件与生成表现，不预设模型一定适合 8 GB 显存。

### Phase 1 后的 UI 精简（2026-10-16）

用户追加要求：减少小灰字、圆角卡片与边框，增强技术工作台感。范围为既有四页的视觉层级和说明文案；依赖现有语义 CSS、原生 details 和既有检查，不添加依赖。

交付：蓝黑工具栏、浅色编辑画布、2–3px 控件圆角、开放式表单；辅助说明按需展开。验收：五种尺寸无横向溢出、导航与键盘可用、桌面聊天生命周期回归、原生截图检查及桌面构建。实际结果见里程碑；本次不进入 Phase 2。

### Phase 2：知识编辑与 3D 探索

2026-10-16：Phase 2A 验收通过（Rust 6/6，浏览器与原生桌面 10/10），停在本切片验收点。

按可验证切片交付：Phase 2A 为二维知识闭环，Phase 2B 为关系修订与 3D 探索。2A 验收门槛：回答片段保存草案 → 确认 → 修改为新草案（原生效版保留）→ 比较并确认 → 重启后版本与来源一致；工作区隔离、并发冲突、升级备份、不可变历史和未保存保护通过。2B 继续执行下述图谱任务；2A 不宣称整个 Phase 2 完成。

依赖：Phase 1 数据持久化稳定；知识版本、审批和关系修订 schema 已确定。

1. 先做知识列表、详情表单、待确认状态、来源关联、版本历史和乐观并发检查。
2. 完成“回答片段 → 草案 → 用户确认 → 编辑为新草案”的二维流程。
3. 加入 7–20 节点确定性测试图，明确标记演示数据；实现选择、聚焦、旋转、平移、缩放和图例。
4. 接入真实知识数据，复用二维检查器；保存布局与视角，切换工作区隔离状态。
5. 增加列表替代入口、搜索筛选、未保存编辑保护和 WebGL 失败提示。

验收脚本：从回答保存草案 → 确认 → 在图谱选中 → 修改并确认新版本 → 查看前后差异 → 重启 → 内容、审批状态和布局正确；仅移动节点不会新增知识版本。

关键检查：版本写入事务回滚、两个编辑入口的版本冲突、非法跨工作区关系、键盘可完成编辑。3D 可用性失败时二维知识操作仍能使用。

### Phase 3：执行图与 Alpha 收口

依赖：Phase 1 的真实事件完整，Phase 2 图谱组件可用。

1. 按运行 ID 从不可变事件生成执行图；没有实现的检索、工具、验证步骤不出现。
2. 展示事件顺序、耗时和完成状态；从回答跳转对应运行，支持列表时间线。
3. 处理失败、取消、崩溃恢复和重启后的部分运行；历史事件不因知识修订而改变。
4. 按 100/500/1000 节点及 1000/5000 边建立基准；分别测试空闲和模型生成期间。
5. 根据结果决定实例化、标签裁剪和 Worker 布局的必要性；先解决测得的瓶颈。
6. Windows 内部安装包与冒烟测试，整理限制、故障说明和版本记录。

验收：完成总纲 Alpha 0.1 闭环；本地数据离线可读；两种图语义明确；提供实际性能记录。60 FPS 与 1000 节点加载 <2 秒保留为目标，未达标时公开限制并收缩支持规模，不将目标写成成绩。

### Phase 4A：授权文件、证据和检索

依赖：Alpha 稳定；导入权限、大小和类型范围已确定。

1. 第一批仅支持 UTF-8 文本和 Markdown；PDF、Office 等复杂解析单列后续任务。
2. 选择文件 → 预览导入清单 → 显示跳过原因 → 确认导入 → 分段与 FTS5 索引。
3. 来源记录内容版本、哈希、定位和授权；回答引用能打开实际片段。
4. 上下文预算、知识版本筛选、相关性排序和截断说明可检查。
5. 源文件变化或删除后提示失效；保留获授权的快照或明确无法重放。

验收：只检索授权范围；可从回答追到真实来源片段；撤销来源授权后未来检索不再使用，历史保留/清理按用户选择执行；检索结果中的指令不能触发系统操作。

### Phase 4B：决策、回滚与结果比较

依赖：证据链可用，知识版本可定位。

1. 决策详情加入备选项、支持/反对依据、假设和复查日期。
2. 完善冲突建议、关系历史、恢复为新版本和变更说明。
3. 固定问题、模型配置和上下文版本，分别运行修订前/后的知识，双栏比较回答、引用、耗时及失败状态。
4. 完成本地一致性备份、恢复、导出和永久删除验证，再开放公开测试。

验收：修改知识后可指出两次运行具体用了哪些不同版本；用户能恢复旧内容为新版本；恢复备份后的消息、知识和来源引用一致。相同输入仍可能存在生成差异，比较报告不自动声称因果关系。

### Phase 5 / 6：按证据扩展

- Phase 5：先有固定问题集、可重复运行和可读报告，再做可视化 DAG；工具调用逐项定义权限。
- Phase 6：用户明确需要训练且数据与硬件评估通过后，建立独立训练服务和留出集评估；研究图与知识图/执行图保持独立。
- 扩展前回答：当前用户受什么限制、有什么真实样例、怎样验收、现有方案为何不足。没有实际需求的基础设施不提前实现。

## 4. 工作项模板

每个开发任务必须写清：

```text
任务：例如停止生成并保留部分回答
用户场景：回答生成中，用户发现方向错误
入口与前置：当前会话有 running 状态的 run
操作与结果：点击停止，保留已有文本，显示已停止，可重新发送
数据变化：运行追加取消事件；部分消息落盘；清理活动请求
异常：完成与取消同时发生；服务已断开；用户切换会话
界面状态：按钮反馈、终态文字、再次发送可用
检查：取消竞争集成检查 + 实际模型手动验证
完成证据：命令、结果、操作记录、已知限制
```

任务按完整用户动作拆分，避免分别把“所有页面”“所有后端”“所有数据库”作为大批次交付。

## 5. 风险与推进规则

| 风险 | 处理方式 | 触发检查 |
| --- | --- | --- |
| 父目录已有 Git 仓库 | 已按用户授权初始化本项目独立仓库；操作前确认当前 Git 根目录，避免提交兄弟项目 | 每次仓库操作 |
| Windows 编译环境缺项 | 记录缺项和具体安装步骤；系统安装另行授权 | 首次构建前 |
| 模型与 3D 竞争 GPU | 单生成、限制 DPR、空闲按需渲染，实测后降级模型或图规模 | Phase 1 基线、Phase 3 合测 |
| 草案覆盖已确认知识 | 分离草案/生效版本，用事务和并发检查更新 | Phase 2 schema 前 |
| 历史来源无法重放 | 版本与授权快照，明确可复现范围 | Phase 4A |
| 界面过载 | 默认收起辅助面板，列表/表单优先，逐页检查主操作 | 每次 UI 验收 |

每个阶段先声明范围和验收标准，再实现、检查、记录。失败项修复或作为明确阻塞，不默认为通过。Phase 0 完成后按总纲要求停在验收点，再决定是否进入 Phase 1。
