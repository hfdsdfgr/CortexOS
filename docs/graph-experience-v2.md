# 三种 3D 视图与交互规范 v2

> 实施状态（2026-10-19）：P0-A / P0-B 已实现上下文快照、真实执行图与实体定位。其余检索、Decision Lab、工作流和评估仍为规划；执行图采用事件投影与确定性布局，细化见 ADR 0007 和 milestone-log。
日期：2026-10-18。状态：待确认设计。保留现有聊天、知识、图谱、设置四个主入口；三种模式位于图谱内。现有知识图为基础，执行图与 Decision Lab 按 [refactoring-plan.md](refactoring-plan.md) 交付；未接入的模式明确标记计划状态。

## 1. 布局与视觉层级

延续蓝黑应用栏、浅色内容区、语义 CSS 和紧凑直角控件。顶部依次显示工作区、图模式、当前对象（知识范围/运行/比较）。模式下只有一行主要工具：搜索、筛选、聚焦、适应视图、保存视图。高级显示参数收进“视图设置”。

主工作区由可折叠索引、一个主要画布和按需显示的详情组成。知识索引用列表，执行索引用时间线，比较索引用版本/运行选择器；详情使用标题、字段列表、正文与局部表单。用对齐、留白和少量区域分隔线表达层级，不堆砌同尺寸圆角卡片。技术感来自准确的数据、可检查状态和稳定的操作结构。

默认显示对象名称、版本/状态与一个主动作。ID、哈希、算法参数放入详情的“审计信息”，辅助说明按需展开；错误和未保存提示持续可见。正文沿用可读字号与对比度，状态同时使用文字/图标，颜色只作辅助。暂不新增粒子、发光或自动旋转。

## 2. 模式语义

| 模式 | 回答的问题 | 节点与边 | 主要操作 |
| --- | --- | --- | --- |
| Knowledge Space / 知识空间 | 项目有哪些知识，它们是什么关系？ | 稳定知识实体；支持/反驳/依赖/来源/修订关系；显示 latest 与 effective 差异 | 聚焦、展开邻域、看来源、编辑草案、确认版本、修改关系 |
| Execution Trace / 执行轨迹 | 这次回答实际用了什么，执行到哪里？ | 本次 run 的真实事件/步骤、输入、固定上下文与输出；时序边和显式数据依赖边分开 | 选运行、定位阶段、检查快照、跳到具体版本/消息、从失败点了解原因 |
| Decision Lab / 决策实验室 | 两个版本/方案的依据和结果有什么变化？ | 固定的知识版本、决策依据、A/B run 和真实评估结果；差异边来自具体版本/引用 | 选择基线与候选、检查差异、重跑固定问题、比较回答和评估 |

Decision Lab 是知识、运行和评估数据的比较投影，不是模型研究图。研究激活或注意力若未来引入，拥有独立入口、方法和限制说明。

## 3. 共同交互契约

| 动作 | 明确结果 | 异常/降级 |
| --- | --- | --- |
| 单击节点或列表项 | 同步选中并打开详情，保持相机 | 节点被筛选隐藏时显示“当前筛选隐藏此节点”，可临时显示 |
| 双击 / “聚焦”按钮 | 镜头对准选中对象，尊重减少动画设置 | 键盘通过列表选择后同样可聚焦；WebGL 不可用时聚焦到详情 |
| 单击关系或详情关系行 | 显示方向、类型、两端名称/版本、来源或变更理由 | 多条重叠边由关系列表区分；没有支持证据就显示“用户声明关系” |
| “展开邻域” | 默认增加一跳且去重，显示新增数量与总范围 | 初始上限 50 节点（待基准调整），可继续加载；收起只隐藏该展开引入且未被其他范围引用的节点 |
| “查看来源” | 打开真实摘录、消息或来源版本，并可跨页定位 | 来源未记录/被删除/未授权分别显示；不跳去相似但不同版本 |
| 返回 | 恢复原模式、选择、筛选与滚动位置 | 保存失败保留编辑；跨工作区目标加载失败保留原位置 |
| 保存视图 | 按知识工作区、执行 run、比较会话各自保存相机/位置 | CAS 冲突保留本地视图，允许读取已保存视图后明确替换 |

键盘通过可访问列表/时间线完成选择、邻域展开、关系检查和跨页定位。画布不是唯一入口。编辑弹窗保留 Esc/关闭时的草稿保护，返回后焦点回触发按钮；窄屏覆盖详情有明显关闭入口。长请求显示加载状态并允许返回，旧请求结果不覆盖新的选择。

## 4. Knowledge Space

沿用现有类型的形状/颜色和确定性布局，布局距离不表示证据强弱或因果。右侧第一屏呈现标题、类型、已确认版本及待确认草案；查看某一历史版本时始终标明版本。

详情分为“内容 / 关系 / 来源 / 历史”，可用轻量标签页或原生折叠，不重复显示同样的说明。关系解释至少含“从 A 指向 B”“关系类型”“修订理由”“修改时间”；关系所依赖的证据未登记时准确说明。新草案保存后仍使用原生效版回答，直到用户确认；显示该影响范围。

“在对话中使用”将节点加入当前会话的上下文选择并展示待发送清单；发送时固定生效版本。没有生效版本时引导审核，不暗中把草案作为已确认知识。知识页与图页定位同一节点/版本，编辑复用 KnowledgeEditor。

## 5. Execution Trace

入口：回答旁“执行轨迹”直接带 runId；图页可按会话/时间/状态选择真实 run。标题显示所属会话、模型、开始时间和终态，运行 ID 收入审计详情。

布局以时间为主轴，输入/上下文依赖置于侧层；默认显示主要阶段，展开阶段查看实际 context items 和事件。图中保持步骤状态文字，失败点和部分输出可直接选择；图底部提供同源二维时间线。点击上下文项打开本次快照内容，并提供“查看知识 vN”和“查看当前版本”两个明确动作。

P0 最小图可以只有接收问题、上下文准备、模型调用尝试/响应、结束或失败。没有检索时详情显示“本次未使用检索”，不添加一个看起来执行成功的检索节点。pending 只出现在单独计划区域；没有记录的验证或工具操作不出现在已执行图。

步骤详情字段：记录类型、状态、真实开始/结束时间（缺失则未记录）、输入输出引用、上下文预算、错误及重试入口。时序间隔标为“事件间隔”，只有同一步真实边界才可标“步骤耗时”。点击重试创建新 run 并保留旧 run，不在图中修改历史事实。

流运行期间只追加真实节点与状态投影，保持用户当前相机和选择；用户可手动“跟随最新”。取消后保留已发生阶段、部分输出与取消事件。应用异常退出后的恢复事件显示恢复时间，结束时刻标未知。

## 6. Decision Lab

先选固定问题和基线 A，再选候选 B；两侧显示模型配置、上下文版本和来源差异。默认以文本差异和回答双栏为核心，3D 只辅助定位新增/删除/变化的依据节点；使用图例、符号和文字表达差异。

P1 可先提供只读知识版本对比入口；P2 才启用真实 A/B 执行和评估结果。关系与证据按实验固定修订解析；历史缺少版本绑定时显示无法完整重建。未执行的一侧显示“尚未运行”，不展示虚构分数。评估指标附评估规则版本、样本数、失败数与评估方法；模型裁判结果标明自动评估而非事实证明。

复跑固定问题创建新 run 并记录比较会话引用。默认保持模型、参数、历史消息和非目标知识相同，只改变目标知识版本；改变其他条件时列入差异清单。随机性和模型标签变更使严格因果结论不成立，界面只展示观察结果。

## 7. 空态、错误与可操作验收

| 场景 | 显示内容与下一步 |
| --- | --- |
| 工作区无知识 | 新建知识 / 从已有回答保存；演示作为独立可选入口，始终带演示标记 |
| 无运行 | 前往当前工作区发送问题；不默认显示演示执行 |
| 旧 run 无快照 | 保留事件和 manifest，标记“历史记录未保存完整快照” |
| 模型离线 | 已存图/版本照常可读，生成入口提供连接设置 |
| WebGL 失效 | 同一数据和选择转到列表/时间线，详情与编辑仍可用 |
| 比较条件不足 | 列出缺少的基线/候选/评估结果，定位到对应选择动作 |
| 未保存布局或正文 | 离开前允许保存、放弃、继续；不同数据类型分别提示 |

交互验收：从回答打开准确 run → 点快照中的知识 v1 → 跳知识页且仍为 v1 → 返回原执行位置 → 再到 Knowledge Space 聚焦同一实体。另测两工作区同名节点、旧版本/失效来源、浏览器前进后退、键盘完整路径、WebGL 降级和窄窗口主动作。目标窗口覆盖 1440×900、1024×768、375px；Windows 150% 缩放另作原生检查，不用浏览器 resize 冒充。

本轮使用 ui-ux-pro-max 本地 `ux` 检索“deep linking predictable back”：Deep Linking 结果适用实体 hash 导航；Back Button 结果标为移动平台，仅借鉴返回可预测原则，不作为桌面测试证据。保留既有设计系统，不生成视觉稿、不声称已做用户可用性测试。
