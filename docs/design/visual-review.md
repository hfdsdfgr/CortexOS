# 对话页视觉验收

日期：2026-10-19。参考：ai-chat.jpg。截图来自隔离测试数据库中的真实Windows WebView2，模型状态和流式内容由明确的本地测试服务提供；真实Ollama由独立回归检查覆盖。截图不是正式用户数据，也没有把参考图用作界面背景。

## 检查方法

Playwright原生测试 `tests/chat-design.spec.ts` 设置1366×768和1920×1080 CSS视口，读取实际DOM尺寸，检查侧栏宽度占16%–18%、输入框处于窗口内、页面无横向溢出。桌面默认DPR1.25；这些是WebView2视口检查，不等于切换Windows系统缩放或手工拖动原生窗口边框。

截图保存于本机 `artifacts/ui-chat/`：

- chat-empty-1366.png、chat-empty-1920.png：空会话、输入草稿、发送可用。
- chat-conversation-1366.png、chat-conversation-1920.png：完整问答与底部输入区。
- chat-streaming-1920.png：真实测试流尚未结束，可停止。
- chat-inspector-1920.png：从回答打开实际执行详情。
- chat-offline-1366.png：服务关闭后检测失败，草稿保留，发送禁用。
- chat-mobile-375.png：窄屏布局；另检查导航抽屉Escape返回焦点。
- reference-comparison.png：参考与1920原生截图并排缩小，分别保持原宽高比并标注来源。

使用系统自带System.Drawing生成并排图；原先尝试Pillow时发现未安装，未增加依赖。已人工查看截图并按布局、留白、排版、输入区域顺序复查。没有计算“相似度百分比”：品牌、语言和功能差异会使逐像素差异分数产生误导。

## 复查与调整

第一版欢迎区偏高，已将空态起点改为按33vh定位，增加标题与输入框间距；保留窄窗口空间约束。侧栏约17%、主区内容宽度约78%和输入区域左边界与参考接近。输入框内重复焦点线改为外框焦点反馈，发送保留鲜明粉色与圆形。

原生行为检查涵盖新建工作区、发送、生成中停止入口、执行详情、离线草稿；原有完整回归继续覆盖取消、断流、重启持久化、知识保存和执行图定位。

## 仍存在的差异

1. 参考为英文空态；本应用使用中文品牌与本地字体，字形、长度与抗锯齿不同，未宣称恢复原字体。
2. Sidebar没有Daily/Developer切换、Skills和Automation；用真实知识/图谱/设置入口替代，项目组是可操作的工作区选择。
3. 输入底条为本地/知识上下文，不提供尚未实现的文件夹授权；模型按钮显示真实配置，禁用状态不强行染成粉色。
4. 顶部保留低强调模型状态与页面标题，Windows窗口按钮使用系统装饰。
5. 1366宽度下为中文控件留出更大点击区域，输入框高度不严格按参考图片等比缩放。现有知识、图谱、设置页面保留原主题，因此跨页存在视觉过渡。

## 下一轮建议（本轮不实施）

用户确认对话方向后，再决定是否将浅色共享外壳推广至其他页面。按实际使用反馈校准侧栏会话密度和欢迎区高度；Windows150%/200%系统缩放、完整屏幕阅读器以及长会话连续滚动应独立验收。功能层继续原P1计划，视觉复刻不改变检索与架构优先级。
