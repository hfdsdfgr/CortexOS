# CortexOS UI Design Direction V3（永久规范）

2026-10-21。用户明确指定的长期视觉与交互标准。与旧视觉规范冲突时以本文为准；业务真实性、来源权限、草稿保护和无障碍要求继续有效。实施范围与验收证据写入 milestone-log，目标不等于已完成。

## 视觉基准与参考分析

首要参考为本地 `reference/ai-chat.jpg`（4797×2763）。原图左侧区域约占17%，主背景接近白色；正文与输入区域居中，输入框约占全图64%宽度。视觉层级来自字体大小、浅灰底与少量强调色，细边框界定可输入区域，阴影仅辅助浮起控件。圆角柔和，正文与导航没有重复套卡片。原图空态的宽阔留白不直接套用到有内容的工作界面。

全局定位：舒适、极简、柔和、克制、现代化、低视觉干扰的个人 AI 工作台。保留64px紧凑导航和必要边框。使用20–40px页面边距、8–16px组内间距、20–28px组间间距，随窗口收缩。常规操作按钮按内容定宽、至少36px高；正文16–17px、行高约1.75。避免小灰字说明常驻和用“·”连接元信息；状态、错误、草稿、来源和必要事实反馈保持可见。

Neo4j Bloom 作为浅色节点/关系阅读方向，GraphXR 作为空间纵深与相机探索方向。此次外部资料读取未成功，因此不把未核实的产品交互写为事实；具体交互按用户提供的 V3 要求实施。

统一连续圆角Token `--v3-corner-shape: superellipse(1.4)`，控件半径16px、浮层28px、输入框32px；图标按钮14px、气泡18px。半径与曲线形状配合调节，避免小半径叠加较方的squircle导致视觉仍像小圆角。所有实际带圆角的公共控件、表单、筛选、图谱检查器和抽屉由同一处规则应用，发送圆按钮保留圆形。当前原生WebView2实测支持；旧运行时保留标准圆角回退。设计目标参考 [Apple continuous corners](https://developer.apple.com/documentation/quartzcore/calayercornercurve/continuous)，网页实现使用 [CSS superellipse](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/superellipse)，属于视觉适配，不宣称逐点等同Apple专有曲线。阴影只用于浮层且保持克制。复用现有 `.button`、`.icon-button`、`.field`、AppShell、KnowledgeInspector、原生 dialog/details；仅出现真实复用需求时抽取新组件，不另建平行控件库。

## 桌面窗口外壳

Windows主窗口关闭系统标题栏（`decorations:false`），启动背景与V3一致。窗口操作整合到现有64px顶栏，不增加第二条标题区。中间空白区域用于拖动和双击最大化/还原，右侧提供最小化、最大化/还原和关闭，尺寸36px，保持键盘焦点与操作名称。浏览器预览不显示这些原生操作；窄内容视口优先保证窗口控件可达。

窗口关闭继续使用Tauri close与原有窗口关闭监听，保留生成取消和未保存编辑保护；模态编辑窗口内可通过系统关闭请求触发同一保护。仅为main窗口添加最小化、最大化切换/状态读取与开始拖动的权限；已有close权限复用。实现依据 [Tauri窗口自定义文档](https://v2.tauri.app/learn/window-customization/)。

## 对话、知识与设置

- 对话沿用紧凑会话侧栏和开放式回答，正文与输入区最大1120px。用户消息随内容定宽，最多占阅读区85%且不超过720px，内边距8px 12px。输入区固定靠近窗口底部，桌面底边12px、窄屏8px；聊天记录使用剩余可用区域滚动，末条消息不附加底部外边距。输入框下方辅助操作桌面合为一行并保持6px行距，窄屏可换行；资料选择和快捷键说明仍可展开。输入框默认一行，文本区最小42px（整体约112px），内边距12px 16px、发送按钮36px，支持原生field-sizing时随文字增长，文本区上限160px，其他运行时仍可换行、滚动及手动调整。输入边框与焦点提示保留。正文17px、行高1.75；欢迎区顶部24px，输入区独立定位到底边，底部使用明确的小间距。
- 知识保留240px列表、可收起入口和最大1040px正文外层。页面标题24px、文档标题28–34px，状态和审核动作按内容定宽。历史使用右侧抽屉；来源、历史和对照按需展开。列表使用浅灰底，不将正文套成卡片。
- 设置保留模型连接、本地数据、关于分类，共用柔和分段切换外观。高级参数和解释按需展开。切换分类保持已有草稿，未保存、成功和错误反馈保留。
- 编辑、确认、资料文件和处理记录复用全局按钮、输入边框和圆角。浮层统一28px连续圆角和轻阴影；筛选/表单/搜索/版本选择统一16px连续圆角，复选框与单选框使用全局强调色。窄窗口内容可滚动，主操作保持可达。
- `design-tokens.css` 管理共享颜色、圆角、宽度和页面边距；`workspace-v3.css` 管理全局外壳/公共控件及上述页面的视觉适配；`graph-design.css` 只保留图谱布局规则。复用现有组件和状态逻辑。

## 图谱页面

- 紧凑标题、类型切换、数据来源、搜索和常用视图操作。类型、审核和日期筛选默认收起，按钮显示已启用的筛选数量。
- 检查器默认隐藏，选择节点后打开；浮层覆盖画布边缘，保持画布尺寸稳定。列表与无WebGL降级入口保持可用。
- 画布与页面使用连续浅灰蓝背景。节点低饱和、带细腻材质高光，保留类型形状；细半透明连线保留方向箭头。禁止纯白球体、大量霓虹、高饱和大色块和强发光。
- 聚焦保留当前可见邻接节点及其位置；“只看直接关联”仍是独立显式操作。筛选/分页/布局不改变知识和关系语义。
- 性能和Benchmark仅在独立测试模式运行。保留既有 graph-baseline / real-graph 项目、环境开关、隔离数据库及报告；常规界面不展示合成性能指标，也不以目标替代实测。

## 相机交互

相机由一个 GraphCamera 控制器管理，统一持有动画和聚焦前快照。

1. 左键拖动旋转，右键拖动平移，滚轮缩放。
2. 点击节点保存探索镜头并平滑聚焦；连续选择其他节点仍保留最初探索快照。聚焦完成打开检查器，可编辑。
3. 拖动画布空白超过点击阈值时，恢复原镜头并接续用户拖动；恢复采用即时应用，避免恢复动画与拖动争夺相机。
4. Esc 或关闭检查器退出聚焦，平滑返回原镜头。动画可被新的聚焦、拖动、滚轮、恢复或重置中断；系统减少动态效果时直接到达目标。
5. 编辑器事件不传到相机；打开 dialog、输入控件编辑时，Esc 由对应控件处理。保留未保存保护。组件卸载时撤销监听与动画。

## 全局应用与验收门槛

用户已要求推进全部剩余V3。共享 AppShell 对所有页面启用 `.design-v3`，对话、知识、图谱和设置及其弹窗/抽屉使用相同主题。执行图复用相机/材质与按选择显示的浮层；回答记录和实际事件列表保持原有功能。后续新增界面直接沿用全局V3，无需再次经过图谱先行的临时门槛。

每轮修改都对照本地原图做实际截图，覆盖默认、选择、展开筛选、编辑以及窄窗口；使用隔离数据并注明浏览器或原生WebView2。相机必须实测旋转、平移、缩放、聚焦、恢复、动画中断和编辑事件隔离。类型检查/构建不能替代视觉检查；无必要不跑单元测试。保留数据模型、业务命令和来源权限；本规范不授权无关重构。


## 图谱阅读补充（2026-10-22）

选中标签优先，其次直接邻接；未选中时优先镜头中的可见节点。有限标签槽避让文字/边界/实际面板，低优先级放不下则隐藏，全文保留在列表和详情。长标题省略但状态独立保留。知识图可在原折叠图例开启相关连线名称，默认关闭；相关边突出，其他弱化，方向和保存事实不变。短引线只用于文字锚定，不作为新业务关系。保留原形状、材质和可中断相机，具体实测与限制见../graph-reading.md。
