# 知识管理增量UI规范

2026-10-20。此版本覆盖同日上一轮“聊天宽侧栏＋列表/历史上下分区”。用户最新要求：紧凑全局导航、可收起列表、居中阅读容器、按需版本历史抽屉。提供的Linear、Notion、Obsidian截图仅用于布局原则；不复制其中的emoji、品牌、暗色外观或未实现功能。

## 文件与阶段

1. components/AppShell.tsx统一全局导航与工作区位置；新增NavigationIcon.tsx原创几何SVG和compact-shell.css。保留ConversationList作为聊天的会话列表，聊天正文/输入组件不变。
2. Knowledge.tsx与knowledge-design.css：知识列表固定260px，仅搜索、状态筛选和条目；工具栏按钮控制收起/展开。
3. 正文最大860px（外层含左右40px内边距最大940px），标题26–34px、正文16px/1.85行高。保留类型、当前版本、生效状态；合并重复列表标题，桌面不再显示冗余返回列表按钮。
4. 历史从列表移出；详情按钮打开右侧380px非模态抽屉，1200px以上为抽屉预留空间，可继续对照完整正文；较窄窗口为覆盖抽屉。关闭/Escape返回触发按钮焦点；切换知识或工作区关闭旧抽屉。历史选择只更新查看版本。

## 设计系统与交互

沿用聊天浅色Tokens、Segoe UI/微软雅黑、低饱和中性色。56px全局图标栏可展开至184px，同进程跨页面保留展开状态；图标具备可访问名称，悬停/聚焦显示Tooltip。原创SVG采用24px画布、1.6px线宽，以错位对话框、层叠知识、连接轨道、调节轴表达四个入口，不使用emoji或栅格图片。

工作区选择和创建移到顶部，各页面同一入口；模型状态保持真实。聊天会话列表240px，原消息、输入、历史会话及新建仍可用。800px以下会话列表使用原生dialog，图标导航保持可见。知识窄屏沿用先列表后详情，返回列表与展开列表可恢复条目；历史抽屉宽度不超过窗口扣除导航后的空间。

用户追加要求主界面不出现小灰字说明。类型/查看版本/审核状态合并为一行14px正常文字；列表状态、来源入口和历史时间使用清晰文字色。解释性来源与审计信息按需展开。条目选中使用浅灰和文字，状态色降为辅助；审核主按钮保留主操作强调。来源与生效版本对照继续按需展开。原有新建/编辑、草稿保护、并发冲突、审核、版本对照、来源摘录/哈希、原会话及图谱/执行定位全部复用原逻辑。没有数据库、知识引擎、模型调用、权限或依赖变更。
