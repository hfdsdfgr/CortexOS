# ADR 0004：本地对话生命周期与上下文预算

状态：已采用，2026-10-15，Phase 1。

## 决定

1. 默认只连接 `127.0.0.1:11434` 的本地 Ollama；不使用代理、不跟随重定向，请求前拒绝云端模型别名和无法确认的模型格式。服务配置关闭云端功能。
2. 全应用一个活动生成任务，用内存预留和 SQLite 唯一部分索引共同约束。跨页面切换不转移运行归属。
3. 输入、运行、回答占位与初始事件同事务写入；输出每 250 ms 有更新时保存检查点，结束追加唯一终态事件。重试创建新 run；失败、停止、中断和达到输出上限的轮次不用于下一次上下文。
4. 上下文选取最近最多 10 个完整成功轮次与当前问题，整轮按 UTF-8 字节保守计费，另预留输出与系统提示空间。记录消息 ID、哈希与系统提示版本。超过预算的当前问题不落盘并保留草稿。
5. UI 使用 Tauri Channel 传递带范围与序号的更新；SQLite 是保存记录的依据。单个 `useStudio` 保存跨页面状态，暂不引入 Zustand。
6. 初始候选 `qwen3:4b` 当前指向 Thinking 版（359d7dd4bcda），实测 `think:false` 仍输出分析式文字并耗尽 512 输出预算。默认改为同系列 `qwen3:4b-instruct`（官方标签 0edcdef34593）；原模型保留供用户选择。模型标签可变，验收另记录实际 ID、量化、大小及配置，不承诺重放完全一致。
7. 保存实际 `done_reason`、输出 token 数与耗时。`length` 显示“达到输出上限”与重试入口，不呈现为完整回答；不自行推断或过滤模型文本中的“分析”段落。

## 原因与限制

目前只有一个窗口、一种供应方和直接对话。使用普通 Rust 模块与 React hook 足够表达状态；不建立插件框架或自定义 tokenizer。保守字节预算可能少用模型上下文，但不会冒充精确 token 统计。模型完成帧提供实际输入/输出 token 数用于实测。

Windows 独占数据目录句柄避免多个进程相互恢复。正常关闭等待当前任务取消并保存；强制退出只保证已提交片段，重启记录 interrupted。未发送草稿仅在内存，关闭窗口会丢失；备份/导出与删除留到独立阶段。

未来会话较大时，为历史消息和运行列表加入分页；需要知识或文件检索时再扩展上下文选择和来源清单。改变预算策略时更新策略版本和执行记录。

参考：[官方 Instruct 模型标签](https://ollama.com/library/qwen3:4b-instruct)、[官方仓库的 Thinking 开关问题记录](https://github.com/ollama/ollama/issues/12917)。以上切换依据也包含本机实际生成与模板检查。
