# ADR 0010 — 回答引用绑定本次实际输入

日期：2026-10-20；状态：实施 P1-B2。

为实际选用的知识按请求内顺序分配 `资料1` 等编号，将编号、原文及来源记录写入同一份模型输入和上下文清单。引用格式为 `[资料1]`（全文）或 `[资料1:2-3]`（知识文字第 2–3 行，含首尾，按换行符分行）。编号仅在一次回答内有效。模型接收引用格式说明；选入数量及格式说明的真实 UTF-8 字节开销参与原容量计算。

回答结束时由 Rust 扫描原始输出，只对本次编号及行界限进行检查，结果作为实际发生的 `citations_checked` 事件，与输出和终态一起提交。保留原始回答、不修正模型引文、不检查论断真伪。取消、失败和启动恢复也检查已经保存的部分文字；旧请求没有本协议时保持原样，不补造历史事件。

沿用 context_snapshots 和 execution_events，不新增数据库表、命令或文件权限。load_messages 只读取已保存的检查结果；引用使用 UTF-16 偏移供 React 定位，重复文字通过明确的行号区分。无效编号、错误格式、越界行或不完整标记显示无法定位，绝不回退到其他运行、最新知识版本或未选中的检索结果。

聊天中引用按钮打开本次实际输入文字，提供知识版本入口及文件原始选段入口。知识正文与最初文件片段分开显示：知识经过修改后，其文件起源不代表文件支持修改后的内容。停用或更新文件不影响历史阅读；跳转固定文件版本，禁止重新读取磁盘。有效引用仅代表位置可找到，不代表论断已证实。已有知识、来源和图谱功能保留。

验收：实际 HTTP 请求等于保存请求；有效/无效/缺失引用；中文和 emoji 偏移；重复行；取消部分输出；知识改版和来源停用后的旧引用；跨工作区拒绝；重启一致；引用详情键盘/Escape、1366×768 与 1920×1080。按用户规范不跑单元测试，仅做代码检查、类型/构建和必要的一条原生整链路验收。
