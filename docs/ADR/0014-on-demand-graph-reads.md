# ADR 0014 — 图谱按需读取契约

2026-10-21。沿用V3与现有表/索引、实体ID、审核及模型逻辑；不增加系统级能力。全量load_knowledge_graph保留为兼容/审计和独立基准入口，正式知识图改用以下工作区限定读取。

- query_graph_nodes：搜索标题、类型、审核状态、本地日期转换的UTC下界、可选直接关联中心；单页最多200，offset分页。返回节点摘要、工作区总数、范围/匹配总数、快照标记及视角。默认坐标使用全工作区稳定排序序号，避免筛选/分页改变位置。
- load_graph_links：只读指定已加载节点之间的当前有效关系；保持方向与稳定ID，不夹带历史。输入节点逐项校验工作区。
- load_graph_node：按具体ID读取摘要/布局序号/已存坐标，服务跨页定位与被筛选隐藏的详情。显式“显示这个节点”才加入画布。
- query_graph_relations：选中节点展开关系时读取当前关系，每页50（包括停用），返回真实总数与所需端点摘要。节点变更后丢弃迟到响应。
- load_graph_edge_history：展开具体关系才读取不可变历史，按version降序、beforeVersion游标、每页50；包含该页端点摘要，保留理由/日期/停用状态。

快照标记基于工作区节点数/修订总和、关系数/最新版本总和及视角修订。现有写入仅追加或增加修订，分页批次若标记变化则拒绝混合结果，保留界面草稿并提供重新读取。所有只读操作在同一个Database连接锁内完成；跨工作区ID拒绝。UI按请求代次丢弃旧筛选/范围的结果，出错不当作空数据。

画布初始最多200节点，直接关联初始50。继续加载会实际执行有界SQL分页；计数明确表示已加载量与真实总数。当前前端按目标显示数量重取前缀页以保持实现简单，已加载旧页可能重复读取；这不是增量缓存或无限规模保证，原始行数和代价需要实测。前缀的每个查询页均不超过200，关系历史不随节点页读取。

关系编辑打开时沿用list_knowledge读取端点选择摘要，冲突时只读取该关系最新修订。save_graph_view现有UPSERT已合并坐标，继续复用；界面只提交改动的坐标，保留未加载位置与并发修订检查。重置仅作用于当前加载范围，标题/操作明确。演示与执行图保留原事实来源。完成该读取闭环及必要原生检查后停止，多中心收起和标签设计另做。


实现边界：当前视图最多10,000节点（显式临时节点占用一个名额），单次保存继续沿用已有1,000个改动坐标限制；这是请求上限，不是已验证的流畅规模。范围搜索在数据库对整个工作区/关联范围匹配，不只搜索已下载节点。ROW_NUMBER、匹配计数与快照统计仍可能扫描工作区；只保证返回页有界，不声称查询CPU成本与工作区总量无关。当前有效关系按已加载端点集合返回，密集关系没有另做边分页。

启用现有rusqlite的functions特性，用确定性Rust小写子串函数保留中文及Unicode标题匹配；SQLite内建lower仅覆盖ASCII。未新增crate、版本、表或迁移，两个锁文件保持原内容。主窗口新增五项实现对应的只读业务命令权限，未新增系统、文件或网络权限。节点与关联中心的摘要可单独读取，筛选隐藏中心时仍保留范围名称。

请求响应仅在对应范围仍有效时提交；恢复视图也受同一范围代次保护。迟到请求可能完成后端读取，但不能覆盖新范围。位置接收只覆盖未改动的节点，手动改动坐标跨筛选保留；重新读取与明确恢复已保存视图是两个独立操作。关系版本更新后提供重新读取关系入口，读取端点失败保留编辑草稿并可重试。
