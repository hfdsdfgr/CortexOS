## 2. P0：可验证的认知闭环

### P0-A：知识版本进入请求与完整快照

**用户动作：** 选择已确认知识 → 提问 → 查看本次实际使用版本；知识新草案不影响回答，确认后下一次请求才使用新版本。

**复用：** `knowledge.rs` 的生效版本/审批事务、`db.rs` 的运行和消息、Ollama 流调用、Chat RunDrawer、KnowledgeInspector。

**修改：** 新 0004_context_audit；在 `models.rs/studio.ts` 增加类型化 manifest/snapshot；改 `prepare_run/start_chat/generate`，增加 `preview_context/get_context_snapshot`。引入明确上下文选择，不做全库自动检索。保存实际 system/messages/options，provider 只消费保存的请求构造产物。事件记录真实边界，兼容 legacy 事件。知识引用类型政策见架构文档。

**界面：** 输入区一行“本次上下文：N 项”，展开可选知识、看版本/预算/排除原因；默认历史消息行为保持兼容。发送前版本变化保留问题并要求更新预览；超预算给出需移除项，不静默丢掉用户固定资料。

**必须验证：**

1. 工作区 A 知识 K 的 v1 已确认；v2 为草案。第一次请求捕获正文只能包含 v1；快照 ID/哈希/顺序与实际 HTTP 请求逐项一致。
2. 确认 v2 后第二次请求使用 v2；第一次快照仍是 v1。未确认或跨工作区节点被后端拒绝，界面草稿保留。
3. 预览到发送间审批变化、组装失败、磁盘写入失败、取消/完成竞争、HTTP 检查失败、断流和重启都有真实终态；快照保存失败时没有模型调用。
4. 0003 旧库升级后运行/事件/知识/关系数据不变；旧运行显示 manifest_only，新运行有完整快照，外键及完整性检查通过。
5. 本地模拟 provider 核对确定性输入；真实 Ollama 冒烟核对运行与保存，不用自然语言完全一致作为测试门槛。

**完成门槛：** 用户能明确指出某次回答用了哪个知识版本及哪些消息，确认新版本可改变下一次真实请求；旧运行不变。提供测试命令/结果和实际调用观察后停止本切片。

### P0-B：统一定位与真实执行图

**用户动作：** 回答旁打开执行图 → 选上下文节点 → 看快照 → 跳到知识具体版本或消息 → 返回原运行。

**复用：** 现有事件表、get_run、RunDrawer、GraphViewport 旋转/聚焦/标签/列表降级、语义 CSS、KnowledgeEditor。

**修改：** 新增 `list_runs/load_execution_graph/save_execution_view`；ExecutionStep 从事件投影，旧事件未知边界保持未知。0005_execution_views 独立保存执行布局；提取展示 DTO 适配现有画布。App/studio 增加 EntityRef 路由与历史；Graph 的本地选中改为共享导航引用，Chat 增加消息滚动定位。API/权限只注册实际使用命令。

**必须验证：** 图节点逐个对应保存事件/快照/输出；成功、失败、取消、恢复中断均可重启查看；没有检索/验证时图中无该执行节点；时序边不冒充依赖。跨页跳转保留具体版本和返回位置，切工作区不串数据，旧请求不能覆盖新页面。WebGL 失效仍可通过同源时间线完成检查。

**完成门槛：** “问题 → run → 快照 → 实际模型调用 → 事件/输出 → 3D → 节点详情”原生桌面全链通过。运行详情能在模型服务关闭时读取。P0 完成后先确认体验，再扩展检索。

## 7. 原审计轮验收与停止点

### P0-A 实现细化

get_run 直接返回 snapshot，复用现有读取权限，暂不另设 get_context_snapshot。知识选择在当前进程按会话保留，不新增选择表；历史运行依据独立持久化。上下文校验和预算失败属于发送前错误，不创建运行；运行/消息/快照在同一事务提交，数据库写入失败整体回滚且不调用模型。进入模型阶段后所有失败有终态。这避免保存一个已创建但无法安全保存输入的半运行；原计划“先创建运行再组装”调整为原子准备提交。后续异步检索需真正的准备阶段运行时，再增加阶段状态。

模型按标签执行；检查接口未提供 digest 时记录 unknown，不把输入快照称为精确模型复现。新事件边界已拆分；首次上下文组装仍为提交前的同步工作，接收/准备时间戳表示持久化记录时间，不宣称是组装耗时。


### P0-B 实现与验收（2026-10-19）

已接入实际事件/快照/输出投影、运行分页、实时更新、具体版本/消息定位及返回导航。复用 GraphViewport、KnowledgeInspector 和原执行表，新增三个业务命令；运行级视角由 0005_execution_views 保存。节点位置按事件顺序确定，不新增 execution_positions；ExecutionStep 当前为只读事件投影，尚无工作流依赖 DAG。具体决策见 ADR 0007。

验收证据与实际命令见 milestone-log。P0 交付后停止，待用户确认再实施 P1-A；原 Phase 3 大图性能与安装包不计入本次完成范围。

### P1-A 实现细化（2026-10-19）

用户确认默认开启、会话级关闭、中文夹杂英文术语和代码。0006_knowledge_retrieval将来源导入迁移分开：本次只包含FTS派生索引、会话偏好及不可变候选记录。同步查询与P0原子准备合并，实际开始/结束时间先捕获后随运行提交；准备失败仍保留草稿而不创建半运行。手动优先，自动最多20候选/5纳入且使用手动选择后剩余预算的一半；历史消息使用后续剩余预算。完整规则及固定样本边界见ADR0008，实际验收见milestone-log。
