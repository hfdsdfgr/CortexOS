状态：实施规范 v0.2，2026-10-16。依据：`../development.md`。

本文将总纲转为实施约束。项目已推进到 Windows 预发布与验收；实现与实际验收见 `milestone-log.md`。后续数据结构设计在对应阶段实现和验证。

## 1. 产品定位与优先级

CortexOS 是 Windows 本地 AI 项目工作台。核心价值是让用户保留项目上下文、追溯回答依据、审核知识修改，并比较修改后的结果。

核心闭环：创建工作区 → 连接本地模型 → 对话 → 查看本次实际使用的上下文和执行过程 → 保存知识草案 → 审核与修改 → 再次使用。

- 第一优先：数据不丢、状态真实、下一步明确。
- 第二优先：对话、知识编辑、证据定位和版本比较顺畅。
- 第三优先：3D 关系探索及性能优化。
- 模型研究、训练、可编排工作流沿用总纲的后续阶段，不进入 Alpha。

“已确认”表示用户审核过，不等于客观真理已被系统验证。对外文案用“执行过程”，不用“真实思维链”。

## 2. 信息架构

固定应用框架：顶部工作区切换与模型状态；左侧主导航；中间任务区；按需展开的右侧详情区。设置固定在导航底部。

| 入口 | 用户目的 | 默认呈现 | 主要动作 |
| --- | --- | --- | --- |
| 对话 | 询问项目并继续工作 | 会话列表 + 对话正文 + 底部输入区 | 发送 / 生成期间停止 |
| 知识 | 查找、审核、维护知识 | 可筛选列表 + 详情编辑 | 新建知识；审核时确认草案 |
| 图谱 | 探索关系与定位依据 | 图谱画布 + 可折叠检查器 | 搜索、筛选、聚焦 |
| 设置 | 配置模型和本地数据 | 分类菜单 + 分组表单 | 保存设置 / 测试连接 |

“执行过程”从回答旁打开，同时可在图谱页切换“知识关系 / 执行过程”。两种图不叠加；执行过程必须显示所属会话、运行时间和运行 ID。未实现的研究图不出现在正式导航。

上下文属于当前会话，当前从回答的“执行过程”检查实际清单；输入区折叠说明提供选择规则。后续检索阶段再增加上下文管理入口；不把内存、决策、来源、运行历史都做成并列一级导航。决策先作为知识类型及专用详情模板。

## 3. 关键用户流程

### 3.1 首次启动

1. 欢迎页仅提供“创建工作区”和已有数据恢复入口（恢复功能实现后展示）。
2. 创建工作区仅要求名称；先使用应用本地数据目录，不要求用户理解数据库路径。
3. 检查本机 Ollama，展示“服务未运行 / 未找到模型 / 可以使用”的具体结果。
4. 已安装模型可选择并测试连接；未安装时提供可复制的操作说明，下载前说明体积和联网需求。
5. 用户可跳过模型连接，查看已有对话、维护本地知识；发送按钮旁显示连接入口。

不自动安装服务或下载模型。连接失败保留已填配置。高级模型参数放在展开区，默认只展示模型和连接状态。

### 3.2 对话与上下文

- 发送前展示模型名称和上下文摘要；展开后看到纳入的知识版本和来源。
- 发送后立即呈现用户消息与排队/生成状态；生成期间“发送”改为“停止”。
- 全局默认仅一个生成任务；其他会话明确显示哪个会话正在运行，支持跳转或停止，不静默并行。
- Enter 发送，Shift+Enter 换行；输入法组合输入时 Enter 仅确认候选字。
- 停止、断流和超时保留部分回答，标记“已停止 / 生成中断”；重试创建新运行记录。
- 用户上滚阅读时停止强制滚到底部，提供“回到最新内容”。
- 复制、保存为知识、查看来源、查看执行过程置于回答附近；次要动作弱化呈现，键盘聚焦也可发现。
- 没有来源时明确“本次未使用可引用来源”；只有实际纳入上下文且定位存在的引用可点击。

### 3.3 知识审核和版本

1. 选中回答中的内容，点击“保存为知识”。
2. 右侧编辑区显示标题、类型、内容、来源、状态；保存结果默认是“待确认”。
3. 用户可以修改、保存草案、确认、放弃；确认与保存草案使用不同动作名称。
4. 确认时展示实际内容及来源；无来源的手动知识允许确认，但必须显示“用户提供，未附证据”。
5. 编辑已确认知识生成新草案版本；旧确认版本继续有效，直至新版本确认替换。
6. 历史按时间排列，支持查看差异和“恢复为新版本”；旧版本保持不变。
7. 冲突项显示冲突原因和关联知识；由用户解决，模型只提出建议。

知识列表列出标题、类型、状态、来源数量、更新时间；点击整行打开详情。批量动作仅在选中后出现。离开未保存编辑时提供“保存草案 / 放弃修改 / 继续编辑”。

### 3.4 图谱

- 画布占据主体，工具栏固定放置图谱类型、搜索、筛选、适应画布、重置视角。
- 点击节点选中，双击或显式“聚焦”定位；拖动画布不触发节点操作。
- 右侧检查器展示完整文本、来源、关系及版本，编辑沿用知识页表单。
- 悬停仅提供辅助预览，关键动作始终可通过选中节点完成。
- 默认显示选中节点及邻近标签，其余按缩放和密度裁剪。
- 关系方向与名称可查看；空间距离仅表示布局，不表示因果或可信程度。
- 提供可搜索的节点列表和执行时间线，支持键盘完成查看与编辑；WebGL 失败仍可使用这些入口。
- 图例用颜色加图标/形状和文字区分类型；待确认、已确认、有争议使用独立状态标记。
- 不默认自动旋转，不用持续粒子和发光装饰争夺注意力。

## 4. UI 视觉规范

视觉方向：深色工具栏与浅色编辑画布组成技术工作台。顶部与主导航使用蓝黑色，会话栏使用浅灰蓝色，正文使用白色。以背景分区、字号、留白和对齐体现层级，分隔线只用于真实分组。

| 项目 | 初始约束 |
| --- | --- |
| 基础色 | 工具栏 `#182637`；会话栏 `#F0F3F7`；内容 `#FFFFFF`；正文 `#182332`；次要文本 `#526173`；强调色 `#225ED8` |
| 状态色 | 成功 `#167245`；提醒 `#8A5700`；错误 `#B42318`，必须伴随文字；组合上线前测量对比度 |
| 字体 | 本地系统字体：Segoe UI、Microsoft YaHei UI、sans-serif；代码使用本地等宽字体，不依赖在线字体 |
| 字号 | 页面标题 22–24px；分区标题 16–18px；正文 15–16px；工具栏/元信息 13–14px |
| 阅读密度 | 正文行高约 1.6；中文长文约 35–45 字/行；长回答限制宽度，表格允许区域内横向滚动 |
| 间距 | 4/8/12/16/24/32px；常规内容边距 24px，紧凑窗口 16px |
| 圆角 | 输入与按钮 2–3px；浮层 4px；区域容器与导航不加圆角；圆点用于运行状态 |
| 阴影 | 只用于菜单、弹窗等浮层；常规列表与内容区使用分隔线 |
| 尺寸 | 导航约 72–88px；会话栏 220–260px；检查器 320–380px；主体弹性伸缩 |
| 动效 | 状态过渡约 120–180ms；动效解释展开、切换和选择；遵守减少动态效果偏好 |

强调色用于当前选中项、焦点和主要操作。每个当前任务区保留一个主操作，其余用次按钮或文字按钮。危险操作放在次级菜单，并说明影响范围。

常驻文案只保留当前动作所需信息；同一事实在同一视图表达一次。快捷键、上下文规则、模型建议与隐私说明使用可键盘展开的 details；失败、输出截断、未保存修改和未开放状态持续可见。

### 组件选择规则

- 同类可比较对象使用列表或表格；配置使用分组表单；历史使用时间线；版本使用差异视图；关系使用图。
- 卡片仅用于确实独立的对象预览，大小由内容决定。禁止把每条设置、指标、知识、操作都包成等尺寸圆角卡片。
- 不用无业务意义的统计卡片做首页，不用大面积欢迎横幅挤压实际工作区。
- 不把“拒绝卡片”替换成满屏细边框和机械网格；分隔线只表达真实分组。
- 弹窗用于必须即时完成的确认；详情和编辑优先使用稳定侧栏或独立页面，避免连续弹窗。

### 窗口与可访问性

- 验收窗口：1440×900、1280×800、1024×768，并检查 Windows 125%/150% 缩放。
- 宽度不足时依次收起检查器、会话栏；检查器改为抽屉，保留主体阅读空间。
- 更窄窗口切换单任务布局，不强行挤压三栏。正文和主操作保持可达。
- 正文对比度至少 4.5:1；控件边界与焦点至少 3:1；不能仅凭颜色表达状态。
- 全流程键盘可操作；弹窗管理焦点，关闭后回到触发控件；图标按钮提供可访问名称。
- 点击区域常规不小于 32×32px；触控场景至少 44×44px；密集表格也保留清晰命中范围。
- 流式回答不逐字触发读屏播报；播报生成开始、结束和失败等必要状态。

## 5. 状态与文案

| 状态 | 用户看见什么 | 可执行动作 |
| --- | --- | --- |
| 空工作区 | 当前没有对话，说明可以先做什么 | 新建对话 / 连接模型 |
| 模型未连接 | 本地模型服务未连接，已保存数据仍可查看 | 重新检测 / 打开设置 |
| 无模型 | 服务可用，但没有可用模型 | 查看安装说明 / 重新检测 |
| 加载中 | 局部加载反馈，保留页面结构 | 长任务可取消 |
| 生成失败 | 失败原因、部分内容和运行详情 | 重试 / 复制内容 |
| 保存失败 | 草稿保留在编辑区，明确未保存 | 重试保存 / 复制草稿 |
| 搜索无结果 | 当前筛选条件和无结果说明 | 清除筛选 |
| 来源失效 | 文件已移动或内容版本不同 | 查看已存定位信息 / 重新授权定位 |
| 未实现功能 | 开发占位页明确说明尚未接入 | 返回可用功能；不展示假成功 |

常规成功使用轻提示；阻止继续工作的错误原位持续显示。错误信息说清“发生什么、数据是否保留、如何处理”，不只显示错误码或“操作失败”。断网与本地模型服务停止分别处理。

## 6. 实现规则

### 结构与依赖

- 沿用 Tauri 2 + React + TypeScript + Rust + SQLite 技术方向。
- 初期只建立 `apps/desktop` 和当前需要的 `docs`；出现真实跨模块复用后再提取包。
- 默认建议采用 rusqlite：单机事务路径直接、同步接口易于审查；数据库操作进入阻塞任务，不阻塞异步网络和 UI。最终决定在 Phase 0 ADR 中确认。
- 组件内状态优先留在组件；Zustand 只存跨区域交互状态，SQLite 是持久数据真相。
- 复用一套表单、详情检查器和状态标签，避免知识页与 3D 页各写一套编辑逻辑。
- 初始化时核验兼容版本并提交锁文件；当前文档不把未核验版本写成已安装事实。
- 不预建插件系统、微服务、通用 DAG 引擎或多供应商框架。

### 数据与异步

- 前端经类型化 Tauri 命令/事件访问 Rust；所有权限检查、数据库和文件读取在 Rust 完成。
- 每条流事件携带 workspaceId、conversationId、runId 和序号；切换页面后不把旧回答写入新会话。
- 取消、超时、正常结束只能确定一个运行终态；清理监听、请求和布局任务。
- 模型生成不跨越长数据库事务；输入先保存，输出按有界批次检查点保存，正常退出等待落盘；异常退出可能丢失最后一批未落盘文字，恢复时明确标记中断。
- 模型回答作为不可信内容渲染；Markdown 禁止原始 HTML，限制链接协议，不执行代码块。
- 工作区隔离由查询条件和约束共同落实，测试使用两个工作区验证。
- 可见内容、命令类型和数据库状态使用同一套明确的枚举映射。

### 总纲需要补齐的数据语义

1. **事件与状态分离。** 增加只追加的 `execution_events`：run_id、seq、kind、occurred_at、payload；唯一约束 `(run_id, seq)`。开始、完成、失败分别追加事件。`execution_steps` 若保留，只作可重建投影，不能同时声明其每行不可变又原地更新状态。
2. **版本与审核分离。** 为知识版本记录审批状态与审批事件，区分最新草案和生效版本。每次内容修改新增版本；确认动作原子切换生效版本，带预期版本检查。
3. **关系也要留史。** 节点间关系和证据链接的变更写入修订记录；回滚时明确恢复的节点版本和关系范围。
4. **复现实验保留内容。** manifest 的 ID、哈希和版本用于定位；需要精确重放时额外保存受权限约束的上下文快照。源文件已变且无快照时标记“无法精确重放”，不能仅靠哈希声称可复现。
5. **来源指向具体修订。** 证据链接关联节点版本和来源内容版本；源内容变化后保留原引用，新增修订并提示重新审核。
6. **位置独立保存。** 知识布局与执行布局使用明确的对象类型/表约束；视角移动不产生知识修订。

上述更改必须在对应阶段先更新 schema/ADR 和迁移方案，再实现，不能到 UI 阶段临时补字段。

### 安全与数据恢复

- 默认仅连接获准的本机模型端点；导入仅访问用户明确选中的文件或目录。
- 导入展示范围、文件数量、类型、大小及跳过原因；重新定位和递归导入都明确授权范围。
- 来源内容作为资料，不能触发工具执行；模型建议不构成文件或系统操作授权。
- SQL 参数化；路径规范化并检查越界；日志默认不含对话、文档正文和凭据。
- 删除对象默认进入可恢复状态；永久删除单独确认范围和关联数据。
- SQLite 备份使用一致性备份机制，不在运行中简单复制单个数据库文件；迁移前备份，恢复后检查完整性。
- 备份/恢复和导出在公开测试前完成。云端服务未来引入时单独设计数据出设备提示与授权。

## 7. 交付完成标准

每个功能必须同时交付正常流程、空态、加载态、错误恢复和必要的可访问操作。

- 提交前执行对应类型检查、构建及有意义的逻辑/集成检查；占位功能不计入完成。
- 事务、取消、流解析、工作区隔离、权限和版本并发必须有可运行检查。
- UI 验收记录窗口尺寸、缩放、操作步骤及结果；未实测截图/GUI/性能明确写“未验证”。
- 3D 帧率、加载时长和显存数据来自目标设备实际测量，区分空闲和模型生成期间。
- 每阶段记录变更文件、实际命令、通过/失败、已知限制和下一阶段入口条件。

设计依据说明：UI/UX 技能的初次检索返回营销站模板，与桌面工作台不匹配；缩小检索后无匹配结果。本文采用技能的一般交互原则及本项目任务流程推导布局，不沿用该营销模板，也不声称经过用户测试。


### Phase 2B 图谱交互补充

当前工作区与演示数据使用明确的单一切换入口，演示不写入数据库。节点列表可搜索，并与画布共用选中状态；右侧复用 KnowledgeInspector，知识编辑使用同一 KnowledgeEditor。窄窗口依次收起节点索引、改为详情覆盖层，保留关闭和列表入口。类型由颜色、形状与文字共同表达。

相机与位置由“保存视图”明确保存，未保存状态持续显示。重置布局恢复确定性坐标并标记未保存；恢复已保存视图明确替换本地未保存布局。位置编辑属于视图操作，不产生知识修订。关系保存表示用户确认该关系，修改和停用追加修订；冲突时保留表单，读取最新关系后由用户比较再保存。


### P0-A 上下文规则

上下文选择显示生效版本内容；图/知识列表的最新草案不可代替实际请求输入。版本变化时保留问题并要求重新选择。预览为只读、非执行事件；实际请求与保存快照使用同一构造对象。检查模型、发送尝试、收到响应分别记录；遗留事件保留原值并用准确文案解释。新增事件不能使旧运行显示虚构成功阶段。


### P0-B 执行检查规范

用运行选择、事件索引、聚焦画布和详情构成任务布局。默认显示阶段摘要与内容，原始 payload/哈希/配置按需展开。画布与列表共用节点选择；WebGL 失效时列表仍能查看内容和跨页定位。聚焦/适应按钮在画布就绪后启用。消息定位取得键盘焦点，根页面焦点不能覆盖目标消息。知识跳转显示运行引用的明确版本，版本缺失时呈现错误。

执行图保存仅影响相机与目标点；未保存状态可见，同进程跨页返回保留视角草稿，重启恢复显式保存值。关系说明区区分记录顺序、上下文纳入和输出保存。

### 2026-10-19 参考图对话布局覆盖

用户明确指定参考图作为对话视觉标准；对话页采用浅色Sidebar合并主导航、工作区和会话，TopBar保留模型状态，空态使用居中欢迎区和宽输入框。此规则覆盖本文件早期对话线框的双侧栏和深色外壳规定，仅限对话页。Tokens与交互细节见design/ui-spec.md；其余页面保留现状。

### P1-A 上下文检索交互

输入条用“自动检索知识”表示会话级持久化偏好，用“手动选择：N项知识”表示固定资料数量，避免把手动数量当作实际总上下文。开关操作立即反馈、保存中禁用重复操作与发送，失败恢复保存值并保留草稿。预览、执行详情与检索图节点共用候选说明：纳入/手动已选择/预算排除/条数排除；无命中与关闭明确区分。候选默认折叠，保持当前任务界面简洁。


### 2026-10-20 界面用词

面向用户用“添加文件、保存的副本、选用资料、处理记录”等直接表达；必要技术名用通俗名称加括号说明，保留单位、范围、权限和事实边界。预览与实际执行、保存草稿与用户确认、用户确认与事实核实分别准确表达。解释放在相关展开区中。示例与审核清单见design/plain-language.md。

### 当前UI基线（2026-10-20）

用户最新微调以design/reference-ui-implementation.md和workspace-design.css为准：64px导航、浅色背景和紫色强调、正文限宽、按钮按内容定宽且常规36px、列表默认收起及说明按需展开。新增功能复用这些Tokens和控件；只在需要的任务区增加操作。图谱显示范围、读取范围和持久数据分别准确说明，合成基准与实际模型生成分开记录。
